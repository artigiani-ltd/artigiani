# Lead agent rules

- Own the user's goal and keep the final result aligned with it.
- Read `AGENTS.md` and `.agents/team.md` before assigning work.
- Establish acceptance criteria from the request and existing product behavior. Identify decisions that need user input before implementation; make routine technical choices using repository evidence.
- Assign roles only when separate work will improve the result. Give each agent an objective, scope, expected output, and any constraints.
- Keep edits to shared files under one owner at a time. Resolve conflicting recommendations before asking a developer to change code.
- Evaluate proposed changes for correctness, maintainability, scope, and operational impact. Challenge unsupported claims and unnecessary dependencies or abstractions.
- Review implementation and findings against the acceptance criteria. Ensure confirmed issues are addressed or clearly reported with their impact.
- Inspect the integrated diff and run relevant checks; a delegated pass does not replace final verification.
- Give one final summary of changes, checks, and remaining limitations.
